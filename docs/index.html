Should you stop paying for the LLM API?

A build-vs-buy calculator for any team using a frontier LLM (Claude Sonnet 4.6, GPT-4o, etc.) to classify short text — support tickets, leads, product categories, emails, claims, etc. Based on a real benchmark on Banking77: in-house DistilBERT matches Sonnet 4.6 at n=2,500 labeled examples, then runs ~750× cheaper per query and ~50× faster. The methodology transfers — only the exact crossover number varies by task.

Move the sliders to your own situation. The recommendation updates live.  ·  Methodology & source

When does this apply to your situation?

Three questions to ask before reading the calculator output:

  1. Do I have ~2,500+ labeled examples (or can I get them)? If no, keep paying the API — start labeling first. The quality math doesn't work below this threshold.
  2. Am I serving >70,000 classifications per month? If no, the $360/mo fixed self-host cost likely exceeds your API bill, even if quality matches.
  3. Are my classes domain-specific (terminology the LLM has no special leg up on)? If yes, the Banking77 crossover applies. If your taxonomy is general-knowledge (news topics, broad sentiment), expect a higher crossover.

If yes to all three, the calculator below gives you concrete numbers for your situation. If no to any, the framework still tells you what to fix first — data, volume, or task framing.

Beyond banking — where else this applies

Banking77 is the worked example. The same decision math applies to any team running an LLM classifier on short text:

  • Support ticket categorization (any SaaS)
  • Sales lead qualification (sales tech)
  • Product categorization (e-commerce, often 100s of classes)
  • Inbox routing (email / productivity tools)
  • Insurance claims triage
  • Content topic tagging (publishers, platforms)
  • Legal document classification
  • Patient query routing (healthcare, within established taxonomies)

The exact crossover n changes with your specific class count and difficulty — narrower taxonomies need fewer labels, more confusable categories need more. The methodology (measure crossover, compute break-even, audit for label noise) transfers regardless of vertical.

The data behind it

DistilBERT (66M parameters) fine-tuned across 8 training-set sizes vs Sonnet 4.6 zero-shot. Crossover with Sonnet's macro-F1 = 0.891 happens at n=2,500 for the 5-seed ensemble. Statistical significance verified with paired bootstrap (5,000 iterations): the +0.019 gap at n=2,500 has a 95% CI of [+0.006, +0.030] — clearly excludes zero.

DistilBERT macro-F1 by training-set size (5-seed ensemble, blue). Sonnet 4.6 zero-shot baseline as red dashed line. Crossover at n=2,500.

What's in the repo

Four Jupyter notebooks (data prep, LLM baseline, fine-tune sweep, analysis), 40 model run predictions in parquet, the raw LLM prompts and responses, the model checkpoint reference, a cost decision table for five common business scenarios, and per-notebook walkthrough docs explaining each design choice. Everything reproducible from scratch on a free Colab T4 GPU.
