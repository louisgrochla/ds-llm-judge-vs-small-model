Should you stop paying for the LLM API?

A build-vs-buy cost calculator for any team using a frontier LLM to classify short text — support tickets, leads, product categories, emails, claims. It compares a per-query API bill against a fixed self-hosting cost, and shows what quality each label budget bought on Banking77.

Correction — 28 July 2026: the quality comparison is withdrawn

This page previously stated that an in-house DistilBERT matches Claude Sonnet 4.6 at n=2,500 and runs ~50× faster. Both claims have been withdrawn.

  • The LLM baseline was invalid. The test set was sent to the model ordered by class, so each prompt implicitly narrowed the choice from 77 intents to about four. The resulting 0.8913 is not a measurement of zero-shot performance, and no parity claim can rest on it.
  • The latency figure was never measured. No latency measurement exists anywhere in the underlying repo. The "~30 ms vs ~1,500 ms" comparison has been removed rather than restated.

The cost arithmetic below is unaffected — it is division on published list prices, and those inputs are stated. What you cannot currently get from this page is the answer to "will the small model be good enough?" That requires the rebuilt baseline.  Full correction notice and reproduction steps.

When does this apply to your situation?

Three questions to ask before reading the calculator output:

  1. How many labeled examples can I get? The quality figures below show what each budget bought on Banking77. The budget at which an in-house model reaches parity with a given LLM is exactly what is pending re-measurement — bring your own parity target.
  2. Am I serving enough volume to clear the fixed cost? Break-even is fixed monthly cost ÷ per-query API cost: ~68,600 queries/month uncached, ~245,000 with prompt caching, at the list prices used here.
  3. Are my classes domain-specific (terminology the LLM has no special leg up on)? If your taxonomy is general-knowledge (news topics, broad sentiment), expect the LLM to stay competitive to higher n. If it is historically accreted and idiosyncratic — most real ones are — expect the opposite.

The cost side of this calculator is arithmetic and transfers directly. The quality side is one worked example, and its LLM comparison is currently withdrawn.

Beyond banking — where else this applies

Banking77 is the worked example. The same decision math applies to any team running an LLM classifier on short text:

  • Support ticket categorization (any SaaS)
  • Sales lead qualification (sales tech)
  • Product categorization (e-commerce, often 100s of classes)
  • Inbox routing (email / productivity tools)
  • Insurance claims triage
  • Content topic tagging (publishers, platforms)
  • Legal document classification
  • Patient query routing (healthcare, within established taxonomies)

The quality curve changes with your class count and difficulty — narrower taxonomies need fewer labels, more confusable categories need more. The method (measure your own quality curve, compute your own break-even, audit your labels for the noise floor) transfers regardless of vertical.

The data behind it

DistilBERT (66M parameters) fine-tuned across 8 training-set sizes × 5 random seeds on Banking77. Reported as a 5-seed soft-vote ensemble. Uncertainty is a paired bootstrap 95% confidence interval over 2,000 resamples — the repo computes intervals only, and no p-value is produced anywhere in it. Note also that at n≥5,000 the five seeds share most of their training rows (98% pairwise at n=9,000, because the sampling pool is only 9,203), so the spread there reflects training nondeterminism rather than sensitivity to which examples were labelled.

DistilBERT macro-F1 by training-set size (5-seed ensemble, blue). The red dashed LLM baseline drawn on this figure is the withdrawn 0.8913 measurement — disregard that line. The figure is retained for the DistilBERT curves only.

What's in the repo

Four Jupyter notebooks (data prep, LLM baseline, fine-tune sweep, analysis), 40 model run predictions in parquet, the raw LLM prompts and responses, the model checkpoint reference, a cost decision table for five common business scenarios, and per-notebook walkthrough docs explaining each design choice. Everything reproducible from scratch on a free Colab T4 GPU.
